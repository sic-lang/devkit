# github-actions

The `github-actions` module checks the workflows, every regular `*.yaml` and `*.yml` file under `.github/workflows` that Git tracks, with [actionlint](https://github.com/rhysd/actionlint).
It generates the workflow `.github/workflows/checks.yml` with the `files` module.
That workflow calls devkit's reusable workflow [`flake-checks.yml`](https://github.com/sic-lang/devkit/blob/main/.github/workflows/flake-checks.yml), which the `devkit:adopt` skill describes, at the commit of devkit that the repository's `flake.lock` locks.

## Set it up

The module is set up in three steps:

1. Import `inputs.devkit.flakeModules.github-actions`, as the `devkit:adopt` skill shows.
2. Run `nix run .#setup-files`, which writes `.github/workflows/checks.yml`, and commit the file.
3. Run `nix run .#check-actionlint` and `nix run .#check-files`.

## Add to the workflow

The option `devkit.github-actions.settings` holds the repository's additions to [the workflow](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) `.github/workflows/checks.yml`, which the module writes together with its own settings.
A setting that the module also sets to a different value fails the evaluation of the flake.
This example also runs the checks every week:

```nix
perSystem.devkit.github-actions.settings.on.schedule = [ { cron = "0 6 * * 1"; } ];
```

## Update devkit

After an update of devkit in `flake.lock`, `check-files` fails until `nix run .#setup-files -- --force` rewrites the workflow with the new commit.
Commit the workflow with `flake.lock`.

A version of devkit that no commit holds, such as a clone with uncommitted changes given to [`--override-input`](https://nix.dev/manual/nix/latest/command-ref/new-cli/nix3-run.html#opt-override-input), has no commit to pin.
With such a version, the module does not generate the workflow, so the setups and checks leave the committed one as it is, and Nix prints a warning.
