# github-actions

The `github-actions` module checks the workflows, every regular `*.yaml` and `*.yml` file under `.github/workflows` that Git tracks, with [actionlint](https://github.com/rhysd/actionlint).
It generates the workflow `.github/workflows/checks.yml` with the `files` module.
That workflow calls devkit's reusable workflow [`flake-checks.yml`](https://github.com/sic-lang/devkit/blob/main/.github/workflows/flake-checks.yml), which the `devkit` skill describes, at the commit of devkit that the repository's `flake.lock` locks.

## Set it up

The module is set up in three steps:

1. Import `inputs.devkit.flakeModules.github-actions`, as the `devkit` skill shows.
2. Run `nix run .#setup-files`, which writes `.github/workflows/checks.yml`, and commit the file.
3. Run `nix run .#check-actionlint` and `nix run .#check-files`.

## Update devkit

After an update of devkit in `flake.lock`, `check-files` fails until `nix run .#setup-files -- --force` rewrites the workflow with the new commit.
Commit the workflow with `flake.lock`.

The module takes the commit from devkit's flake.
When that flake has none, as when the repository tries a local devkit with [`--override-input`](https://nix.dev/manual/nix/latest/command-ref/new-cli/nix3-run.html#opt-override-input), the generated files cannot be evaluated: `setup-files`, `check-files`, `setup`, `check` and `nix flake check` fail.
To run them meanwhile, set `devkit.github-actions.flakeChecksWorkflow` to the reference that the committed workflow calls, `sic-lang/devkit/.github/workflows/flake-checks.yml@<commit>`.
